# やさしいUIの読み物の作り方

調べたこと・まとめ・報告を、1枚の HTML の「読み物」にするときの見た目と書き方です。
文章と余白が主役で、初めて読む人が一読で分かることを目指します。

## 入っているもの

- `reading.css`：共通の見た目。読み物の `<style>` にそのまま入れて使います。
- `reading-style`：見た目をそろえる・書き方を確かめるスクリプト（Python 3.8 以上、追加のライブラリなし）。
- `examples/sample.html`：見本（内容は架空です）。ブラウザーで開くと見た目が分かります。

## 使い方

1. ふつうの HTML で中身を書きます（下の「書き方の決まり」を守る）。
2. `./reading-style apply あなたの.html` で、共通の見た目を入れます。何度かけても同じ結果になります。
3. `./reading-style check あなたの.html`（フォルダも可）で確かめます。問題がなければ「問題なし」と出ます。

`reading.css` の場所を変えたいときは `--css <path>` を付けます。

## 書き方の決まり

### 文章

- 結論から書きます。`<h1>` のすぐ下に、結論を1文だけ `<p class="summary">` で置きます。
- 1段落に1つのこと。短い文で、1文1つずつ書きます。
- 「どこ：」「見方：」のようなラベルと改行（`<br>`）で1段落に詰めません。段落か短い箇条書きに分けます。
- むずかしい言葉は、身近な言い方に置きかえます。詳しい根拠は末尾の `<details>` へまとめます。

### 形

- 本文は `<main>` で包みます。見出しや段落の見た目は `main h1`・`main p` に当てているためです。
- 要素に `style=` を直接書きません。足りない形は `reading.css` に足します。
- その読み物だけに要る分は `<style data-page>` に分けて書きます。`apply` しても消えません。
- わざと違う見た目にするもの（アプリ風の試作など）は、head に `<meta name="reading-style" content="own">` を入れます。`check` の対象から外れます。

### 見た目

- 色は意味のあるところだけに使います。
  - 青：要点・リンク（`.key`、`<a>`）
  - 緑：完了（`.ok`、`li.done`）
  - 赤：エラー（`.err`、`ul.log li.error`）
  - オレンジ：返事待ち・期限が近い（`.wait`）
  - ほかは濃いグレーと薄いグレーだけ。
- ボーダー（線や枠）は使いません。面の明るさの差と余白で分けます。
- 影は浮くもの（メニュー・シート・知らせ）だけ。読み物には浮くものがないので、影は使いません。
- 文字の太さは medium（500）が強調の基本です。600 は見出しだけ。bold は使いません。
- カード・色付きの枠・ボタンを並べたアプリ風の画面にはしません。

## よく使う形

| 形 | 書き方 |
|---|---|
| 結論 | `<p class="summary">` |
| 動きの並び | `<ul class="log">`、済みは `<li class="done">` |
| やること | `<ul class="todo">`、済みは `<li class="done">` |
| 予定 | `<ul class="plan">` の中に `<span class="time">` と内容 |
| 表 | `<table>`（`apply` で罫線なしの形になります）、数字の列は `td.n` |
| 画像の比較 | `<div class="pair">` の中に `<figure>` を2つ |
| 補足・日付 | `.note`・`.meta` |
| 詳しい根拠 | `<details><summary>` |
