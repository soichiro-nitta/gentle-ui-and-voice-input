# やさしいUIの読み物の作り方

調べたこと・まとめ・報告を、1枚の HTML の「読み物」にするときの見た目と書き方です。
文章と余白が主役で、初めて読む人が一読で分かることを目指します。

## 入っているもの

- `reading.css`：共通の見た目。読み物の `<style>` にそのまま入れて使います。
- [`COMPONENTS.md`](COMPONENTS.md)：使える部品の一覧。要素・クラスごとに、何に使うか・見た目・書き方の例。効かないときに見るところも。
- [`examples/today.html`](examples/today.html)：「今日のまとめ」の手本。予定・昨日の動き・ToDo・今後・今日動いたこと の段がそろった1日のまとめです（内容は架空）。
- [`examples/sample.html`](examples/sample.html)：ふつうの読み物の見本（内容は架空）。
- `reading-style`：見た目をそろえる・書き方を確かめるスクリプト（Python 3.8 以上、追加のライブラリなし）。

## 作り方

1. 手本を写して始めます。1日のまとめなら `examples/today.html`、ほかの読み物なら `examples/sample.html` をコピーします。
2. 中身を書きかえます。使うのは [`COMPONENTS.md`](COMPONENTS.md) にある部品だけにします。新しいクラスは作りません。
3. `./reading-style apply あなたの.html` で、共通の見た目を入れます。`<style>` を最新の reading.css に入れ替え、本文を `<main>` で包みます。何度かけても同じ結果になります。
4. `./reading-style check あなたの.html`（フォルダも可）で確かめます。問題がなければ「問題なし」と出ます。
5. ブラウザーで開いて、手本と同じ見た目になっているかを見ます。違うときは [`COMPONENTS.md` の「効かないときに見るところ」](COMPONENTS.md#効かないときに見るところ) を見ます。

`reading.css` の場所を変えたいときは `--css <path>` を付けます。

## 今日のまとめの組み立て

`examples/today.html` は、次の順に段を並べています。段の見出しは `<h2>` です。

1. `<h1>` に題、そのすぐ下に `<p class="summary">` で今日を一言でまとめた総括。
2. **今日の予定**：`ul.plan` で時刻と内容の表。会議のリンクは `span.links`。その下に `p.later`「このあと」と `ul.plan.later` で、明日〜今週の大事な予定を2〜4行。
3. **昨日〜今朝の動き**：`ul.log` で1行ずつ。済んだものは `li.done`（緑のチェック）。失敗は頭に `span.wait`。
4. **ToDo**：`ul.todo` で、今日やる・決める・返事することを急ぐ順に。期限は頭に `span.wait`。
5. **今後**：`ul.todo` で、急がないこと。なければ段ごと出しません。
6. **今日動いたこと**：話題ごとに `<h3>` ＋ `ul.log`。いちばん上に「うまく動かなかったこと」（頭に `span.wait` の「止まった」）。決まったことは頭に `span.key` の「決定」。最後に `<h3>提案</h3>` ＋ `ul.todo` と、`<h3>やったこと</h3>` ＋ `ul.log`。
7. 最後に `<p class="note">` で「何時点の内容か」。

ページの最後の `<script>` は、終わった予定の行を薄くするだけです。なくても見た目は同じです。

## AI に作らせるとき

このフォルダ（`reading/`）を見られる AI に、次のように頼みます。

```text
reading/README.md と reading/COMPONENTS.md を読んで、reading/examples/today.html と同じ組み立てで、
今日（○月○日）の1日のまとめを1枚の HTML にして。
材料：（予定・昨日からの動き・やること・急がないこと・今日動いたことを、箇条書きで貼る）
決まり：
- 部品は COMPONENTS.md にあるクラスだけを使う。新しいクラスや style= は書かない。
- 本文は <main> で包む。h1 のすぐ下に p.summary で結論を1文。
- 1項目1行、短い文で。段の順と見出しは today.html のとおり。
- 書けたら reading/reading-style apply <ファイル> で見た目を入れて、
  reading/reading-style check <ファイル> が「問題なし」になるまで直す。
```

## 書き方の決まり

### 文章

- 結論から書きます。`<h1>` のすぐ下に、結論を1文だけ `<p class="summary">` で置きます。
- 1段落に1つのこと。短い文で、1文1つずつ書きます。
- 「どこ：」「見方：」のようなラベルと改行（`<br>`）で1段落に詰めません。段落か短い箇条書きに分けます。
- むずかしい言葉は、身近な言い方に置きかえます。詳しい根拠は末尾の `<details>` へまとめます。
- リンクは文の中の言葉に付けます。URL や番号だけのリンクを並べません。

### 形

- 本文は `<main>` で包みます。見出しや段落の見た目は `main h1`・`main p` に当てているためです。
- 並びは「広い枠の中で、文章は左寄せ」。枠は 960px で画面の中央、文章は 640px で枠の左に寄せ、画像や表は枠いっぱいまで使います（狭い画面では1列）。
- 要素に `style=` を直接書きません。足りない形は `reading.css` に足します。
- その読み物だけに要る分は `<style data-page>` に分けて書きます。`apply` しても消えません。
- わざと違う見た目にするもの（アプリ風の試作など）は、head に `<meta name="reading-style" content="own">` を入れます。`check` の対象から外れます。
- 頭に結論を置かないページ（1件ずつ並べるだけの一覧など）は、head に `<meta name="reading-lead" content="none">` を入れます。

### 見た目

- 色は意味のあるところだけに使います。
  - 青：要点・リンク（`.key`、`<a>`）
  - オレンジ：返事待ち・期限が近い・止まった（`.wait`）
  - 緑：完了（`li.done`）
  - 赤：エラー（`.err`）。どうしても要るときだけ。ふだんはオレンジで書きます。
  - ほかは濃いグレーと薄いグレーだけ。
- 枠・カード・影は使いません。面の明るさの差と余白で分けます。
- 見出しは小さめのグレーで控えめにし、結論（summary）と本文を主役にします。
- カード・色付きの枠・ボタンを並べたアプリ風の画面にはしません。

## check が見ること

`reading-style check` は、次のものを「直してほしい」と出します。見つかったら終了コード 1 です。

- 本文の見出し・段落が `<main>` の外にある。
- reading.css が古い・書きかえてある（`--fix` で入れ直す）。
- reading.css のほかに `<style>`（data-page なし）や、外の CSS（`<link rel="stylesheet">`）がある。
- reading.css にないクラスを使っている。
- 本文の要素に `style=` がある。
- `<br>` を3つ以上つなげている。「ラベル：」＋改行が2か所以上ある。
- 200字を超える段落がある。
- 頭に結論の段落がない。

本文の文字がほとんどないページ（JavaScript で描く・絵だけ）と、`frag*.html`・`*.before.html`（作業のかけら・前の版）は見ません。
